\section{Conceptual}

\textbf{Q1.} A program is built from exactly three control patterns: \key{sequence}, \key{selection}, and \key{iteration}. Consider the function below.
\begin{verbatim}
int classify(int score) {
    int grade = 0;               // line A
    if (score >= 40)             // line B
        grade = 1;
    for (int i = 0; i < grade; i++)   // line C
        grade = grade + 0;
    return grade;                // line D
}
\end{verbatim}
\begin{enumerate}
  \item[(a)] Which control pattern does line A illustrate?
  \item[(b)] Which control pattern does line B illustrate?
  \item[(c)] Which control pattern does line C illustrate?
  \item[(d)] The lecture's own example (\texttt{larger(int a, int b)}) treats a function's \emph{parameter list} as an instance of sequence --- the values simply arrive, one after the other, before anything else happens. Applying that same reading here: which control pattern does \texttt{classify}'s parameter list \texttt{(int score)}, together with line D's \texttt{return grade;}, illustrate, and why?
\end{enumerate}

\textbf{Q2.} A running C program keeps data in two different regions: the \textbf{stack} and the \textbf{heap}.
\begin{enumerate}
  \item[(a)] State, in one sentence each, what determines \emph{when} a stack variable's storage is reclaimed, and what determines \emph{when} a heap block's storage is reclaimed.
  \item[(b)] Give one scenario where a value must live on the heap because it would not survive on the stack.
  \item[(c)] Give one scenario where the stack is clearly the right choice, and say why using the heap there would be wasteful.
\end{enumerate}

\textbf{Q3.} Distinguish between a \textbf{contract} statement and an \textbf{implementation} statement for the bag ADT introduced in class (operations \texttt{insert(x)}, \texttt{member(x)}, \texttt{size()}). For each of the following, say whether it is part of the contract or of one implementation, and justify in one sentence:
\begin{enumerate}
  \item[(a)] ``\texttt{member(7)} answers yes or no.''
  \item[(b)] ``The values are stored in an array.''
  \item[(c)] ``\texttt{insert(x)} puts \texttt{x} into the bag.''
  \item[(d)] ``\texttt{size()} reports the number of values present.''
\end{enumerate}

\section{Numerical}

\textbf{Q4.} On a 64-bit machine, consider the C declaration
\begin{verbatim}
struct node {
    int   data;
    struct node *next;
};
\end{verbatim}
\begin{enumerate}
  \item[(a)] State how many bytes \texttt{sizeof(struct node)} reports, assuming \texttt{sizeof(int) == 4} and a pointer is 8 bytes, with no padding.
  \item[(b)] A program executes \texttt{struct node *p = malloc(sizeof(struct node));}. State what lives on the stack and what lives on the heap after this line, and what \texttt{p} itself holds.
  \item[(c)] If \texttt{malloc} returns \texttt{NULL}, what must the program do before it dereferences \texttt{p}, and why?
\end{enumerate}

\textbf{Q5.} Consider the two independent requests below, each on a fresh, previously-unused region of heap memory:
\begin{verbatim}
int *a = malloc(3 * sizeof(int));
int *b = calloc(3, sizeof(int));
\end{verbatim}
\begin{enumerate}
  \item[(a)] State the content of the three integers at \texttt{a} immediately after the \texttt{malloc} call, before anything is written to them. Justify from the definition of \texttt{malloc}.
  \item[(b)] State the content of the three integers at \texttt{b} immediately after the \texttt{calloc} call, before anything is written to them. Justify from the definition of \texttt{calloc}.
  \item[(c)] Both calls request the same number of bytes. Name the one guarantee that distinguishes \texttt{calloc} from \texttt{malloc}, and state what it costs \texttt{calloc} to provide that guarantee.
\end{enumerate}

\textbf{Q6.} A program holds \texttt{p = calloc(4, sizeof(int))}, and the four slots currently hold \texttt{5, 10, 15, 20}. It then executes:
\begin{verbatim}
int *q = realloc(p, 7 * sizeof(int));
if (q == NULL) return 1;
p = q;
\end{verbatim}
\begin{enumerate}
  \item[(a)] After this succeeds, state the values in slots 0--3 of the block \texttt{p} now points to, and justify from the definition of \texttt{realloc}.
  \item[(b)] State what can be said about the values in the three new slots (4--6), and justify --- is this the same guarantee \texttt{calloc} gives, or a different one?
  \item[(c)] Suppose instead \texttt{realloc} had failed and returned \texttt{NULL}. Explain why the code checks \texttt{q} rather than reassigning \texttt{p} directly, and what would go wrong with the idiom \texttt{p = realloc(p, 7 * sizeof(int));} written as a single line with no check.
\end{enumerate}

\section{Design}

\textbf{Q7.} Write a complete C function \texttt{create\_node} that:
\begin{enumerate}
  \item[(a)] Takes an integer \texttt{data} as its only parameter.
  \item[(b)] Allocates one \texttt{struct node} (with fields \texttt{data} and \texttt{next}) on the heap using \texttt{malloc}.
  \item[(c)] Checks the result of \texttt{malloc} against \texttt{NULL} and returns \texttt{NULL} on failure (the caller can then decide how to recover).
  \item[(d)] Initialises both fields --- \texttt{data} to the parameter, \texttt{next} to \texttt{NULL} --- and returns the pointer.
\end{enumerate}
State the function's return type and write the body. Your solution must follow the pointer discipline from the lecture: check \texttt{malloc}, initialise every field, and use \texttt{p->field} form.

\textbf{Q8.} Write a complete C function
\begin{verbatim}
int *grow_scores(int *scores, int old_count, int new_count);
\end{verbatim}
that manages a dynamically-sized array of exam scores, following the allocation discipline from the lecture. Your function must:
\begin{enumerate}
  \item[(a)] If \texttt{scores} is \texttt{NULL} (no array exists yet) and \texttt{old\_count} is \texttt{0}, allocate a fresh block for \texttt{new\_count} integers using \texttt{calloc}, so that every slot starts at a well-defined value. Return \texttt{NULL} if this allocation fails.
  \item[(b)] Otherwise (an array already exists), use \texttt{realloc} to grow the existing block from \texttt{old\_count} to \texttt{new\_count} integers, following the check-before-overwrite idiom from Q6(c) --- never assign a possibly-\texttt{NULL} result directly into \texttt{scores} before checking it. Return \texttt{NULL} if this reallocation fails, leaving the original block untouched.
  \item[(c)] On success, return the (possibly moved) pointer to the caller.
\end{enumerate}
In one or two sentences beneath your function, state what --- if anything --- your function guarantees about the content of the newly added slots (index \texttt{old\_count} through \texttt{new\_count}$-1$) in each of the two branches (a) and (b), and explain why the two branches differ on this point.
