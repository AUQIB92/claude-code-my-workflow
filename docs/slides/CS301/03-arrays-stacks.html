From Vocabulary to a Real Structure

What Week 2 gave us. A way to measure cost — \(T(n)\), the classes \(O\)/\(\Omega\)/\(\Theta\), and the best/worst/average distinction — without running any code.

  • That vocabulary was structure-free: it applied to any loop over any array.
  • Today we point it at our first real structure: the array itself, and the first ADT built on top of one.
  • Today’s questions: how is an array’s address computed, and what is the simplest useful ADT we can build over it?

The Calculator Needs a Bracket-Checker

Our running example. The expression processor reads (a+b)*c. Before it can convert or evaluate anything, it must know the brackets are balanced.

  • Reading left to right, an open bracket must wait for its matching close bracket — and the most recent open bracket closes first.
  • That “most recent first” discipline is exactly what a stack gives us.
  • Before we can build the stack, we need the structure underneath it: the array.

Weeks 1–2 built the vocabulary; from here on, each week is a structure, motivated by a job the previous one could not do.

Arrays: What You Already Assumed

You have used arrays since your first C course. int A[10]; declares 10 integer-sized slots, indexed A[0] through A[9].

  • You have always trusted that A[i] is fast — \(O(1)\), independent of \(n\).
  • Today’s first question: why is it \(O(1)\)? What actually happens when the machine evaluates A[i]?
  • The answer is a formula, not a mystery — and once we have it, we can extend it to two dimensions.

An array is not just “several boxes.” It is one formula for turning an index into an address.

Section 1

Arrays and Address Calculation

What an Array Really Is

Definition. An array is a block of \(n\) equal-sized slots stored at contiguous addresses, so any slot’s address can be computed directly from its index (Horowitz and Sahni 2008; Aho et al. 1983).

  • Contiguous: slot \(i+1\) sits immediately after slot \(i\) in memory — no gaps, no pointers between them.
  • Every slot has the same size \(w\) (in bytes) — sizeof the element type, a notion already familiar from Week 1.
  • Because the layout is regular, the address of any slot is computed, never searched for.

The 1D Address Formula

One-dimensional array address.

\[\text{addr}(A[i]) = \text{base} + i \times w\]

where base is the address of A[0] and \(w\) is the size (in bytes) of one element.

  • base: fixed once the array is allocated.
  • \(i \times w\): how far past base slot \(i\) sits.
  • One multiplication and one addition — constant work, regardless of \(i\) or \(n\).

This is why array access is \(O(1)\): the address formula does not grow with \(n\).

Worked Example: Finding A[4]

Setup. int A[6]; with base = 1000 and \(w = 4\) bytes (a C int).

  • \(\text{addr}(A[4]) = 1000 + 4 \times 4 = 1016\).
  • \(\text{addr}(A[0]) = 1000 + 0 \times 4 = 1000\) — base itself.
  • \(\text{addr}(A[5]) = 1000 + 5 \times 4 = 1020\) — the last valid slot for \(n = 6\).

A[6] would compute to address \(1024\) — a real address, but one that belongs to whatever memory happens to follow the array. Nothing stops the formula from computing it; only the programmer’s discipline does.

Picture: the 1D Address Formula

  • Highlighted cell: index \(4\), computed above.
  • Every other cell’s address follows the same one-line formula.

From One Dimension to Two

A table needs two indices. A \(3 \times 4\) grid — int A[3][4]; — has a row \(i\) and a column \(j\), but memory itself has only one dimension: a single line of addresses.

  • Somebody has to decide which order the 12 slots are laid out in along that one line.
  • There are exactly two standard choices — and the choice matters for the address formula, not for what the array can store.
  • Today’s second question: what are those two choices, and how does each compute an address?

Row-Major Order

Definition. Row-major order stores an array row by row: all of row \(0\), then all of row \(1\), and so on (Horowitz and Sahni 2008; Aho et al. 1983).

  • For an \(r \times c\) array of \(w\)-byte elements:

    \[\text{addr}(A[i][j]) = \text{base} + ((i \times c) + j) \times w\]

  • \(i \times c\): skip over \(i\) complete rows, each of length \(c\).

  • \(+\,j\): then step \(j\) more slots into row \(i\).

This is the layout C itself uses for a declared 2D array — the reason A[i][j] and *(A + i*c + j) mean the same thing.

Column-Major Order

Definition. Column-major order stores an array column by column: all of column \(0\), then all of column \(1\), and so on.

  • For the same \(r \times c\) array of \(w\)-byte elements:

    \[\text{addr}(A[i][j]) = \text{base} + ((j \times r) + i) \times w\]

  • \(j \times r\): skip over \(j\) complete columns, each of length \(r\).

  • \(+\,i\): then step \(i\) more slots down column \(j\).

C and most C-family languages never use this order for a plain 2D array — but Fortran does, and it is the reason the two languages disagree about which loop order is cache-friendly.

Worked Example: the Same Cell, Two Formulas

Setup. int A[3][4]; (\(r = 3\), \(c = 4\)) with base = 1000 and \(w = 4\) bytes. Find \(\text{addr}(A[2][1])\) under each order.

  • Row-major: index \(= (2 \times 4) + 1 = 9\); \(\text{addr} = 1000 + 9 \times 4 = 1036\).
  • Column-major: index \(= (1 \times 3) + 2 = 5\); \(\text{addr} = 1000 + 5 \times 4 = 1020\).

The same cell lands at two different addresses — the major order is part of the array’s contract, not an implementation detail you can ignore.

Check Your Prediction

Which formula would you use? A C program declares int A[5][2]; and asks for \(\text{addr}(A[3][1])\).

  1. Row-major: index \(= (3 \times 2) + 1\).
  2. Column-major: index \(= (1 \times 5) + 3\).
  3. Both give the same index for this array.

Turn and talk. Compute both indices. Are they ever equal for a non-square array? What about \(A[i][j]\) on the diagonal of a square array?

The array gives us \(O(1)\) access anywhere. Now restrict that access on purpose.

Section 2

The Stack ADT

A Stack of Plates

An everyday LIFO. You can only take the top plate off a stack of plates, and you can only add a new plate to the top.

  • You never remove the third plate from the top without first removing the two above it.
  • The last plate placed is the first plate removed — Last-In-First-Out, or LIFO.
  • A browser’s back button, a text editor’s undo history, and a function call’s local variables all obey the same discipline.

The Stack ADT

Definition. A stack is a collection with LIFO access: elements are inserted and removed only at one end, called the top (Sedgewick and Wayne 2011; Karumanchi 2017).

  • push(x): add \(x\) to the top.
  • pop(): remove and return the top element.
  • peek(): return the top element without removing it.
  • isEmpty() / isFull(): query the stack’s state.

Sedgewick frames stack, queue, and bag as three collection ADTs that differ only in which element comes out next (p.120).

Naming the ADT, Naming the Implementation

Two different questions. What does a stack do? (the ADT contract.) How is it built? (the implementation.)

  • Today we implement the stack ADT over an array — the implementation we already understand from Act 1.
  • Week 7 will implement the same contract over a linked list — proof that the contract and the implementation are separate ideas.
  • “a stack, implemented here as an array” — “the array is a stack” conflates the two.

Array Implementation: the top Index

One array, one index. Keep the stack’s elements in A[0..capacity-1] and track the index of the most recently pushed element in top.

  • Empty stack: \(\texttt{top} = -1\) — no element has been pushed yet.
  • One element: after one push, \(\texttt{top} = 0\).
  • Full stack: \(\texttt{top} = \texttt{capacity} - 1\) — every slot is occupied.

Picture: the top Index

  • Occupied slots (indices \(0\)–\(2\)): shaded. Empty slots (indices \(3\)–\(5\)): unshaded.
  • top = 2 — the array holds the elements, top is the only thing that changes on push/pop.

After: push(40)

Overflow and Underflow

The two failure modes. Every array implementation of a stack has a finite capacity — both ends of top’s range must be checked.

  • Stack overflow: push when \(\texttt{top} = \texttt{capacity} - 1\) — there is no slot left.
  • Stack underflow: pop or peek when \(\texttt{top} = -1\) — there is nothing to remove.
  • Every correct push/pop checks its boundary first — an unchecked push silently corrupts whatever memory follows the array (Week 1’s array-bounds hazard, recurring here).

The Cost of Push and Pop

Applying Week 2’s vocabulary. Both push and pop do a fixed amount of work: one boundary check, one index update, one array access.

  • push is \(O(1)\) worst case.
  • pop is \(O(1)\) worst case.
  • “Stacks are fast” — incomplete: fast at which operation, in which case?

Name the operation, give the bound, state the case — Week 2’s habit applies to every structure from here on.

Section 3

Applications

Application 1: Are the Brackets Balanced?

The calculator’s first job. Before converting or evaluating (a+b)*c, confirm every open bracket has a matching close bracket, in the right order (Horowitz and Sahni 2008; Aho et al. 1983).

  • ((a+b): unbalanced — one open bracket never closes.
  • (a+b)): unbalanced — a close bracket with no partner.
  • (a+(b*c)): balanced — and note the last opened bracket is the first to close. LIFO, again.

Balanced-Parenthesis Algorithm

Scan once, push opens, pop on closes

for each character c in the expression:
    if c is an opening bracket:  push(c)
    if c is a closing bracket:
        if stack isEmpty:       return false  // nothing to match
        top = pop()
        if top does not match c: return false // e.g. "(]"
return stack isEmpty  // every open bracket was matched
  • A closing bracket with an empty stack, or a mismatched pop, fails immediately — no need to scan further.

Balanced-Parenthesis Trace

char read action stack (top on right)
( push (
a — (
+ — (
b — (
) pop, matches (empty)
* — (empty)
c — (empty)
  • Input: (a+b)*c. Stack is empty at the end \(\Rightarrow\) balanced.
  • Only bracket characters ever touch the stack; letters and operators pass through untouched.

What Failure Looks Like

Two ways the check can fail. Trace (a+b)) and a+b)*(c.

  • (a+b)): after the first ) pops and matches, the stack is empty; the second ) finds an empty stack \(\Rightarrow\) return false immediately.
  • a+b)*(c: the ) arrives with the stack empty (nothing was ever pushed) \(\Rightarrow\) return false immediately.
  • Both failures are detected the instant they occur — the algorithm never needs to look at the whole string once a mismatch is certain.

Application 2: Evaluating Postfix

Why postfix? Postfix (operator after its operands, e.g. a b +) needs no parentheses and no precedence rules to evaluate (Horowitz and Sahni 2008; Aho et al. 1983).

  • Our calculator’s (a+b)*c becomes the postfix string a b + c *.
  • Today: given a postfix string, evaluate it with a stack.
  • Converting infix to postfix is next week’s job — today we only evaluate a postfix string we are handed.

Postfix Evaluation Algorithm

Operands push; operators pop two, push the result

for each token t in the postfix string:
    if t is an operand:   push(t)
    if t is an operator:
        right = pop()
        left  = pop()
        push(left OP right)   // OP is the operator t
return pop()  // the final, only, value left on the stack
  • Order matters: the operand popped first is the right operand — it was pushed last.

Postfix Evaluation Trace

token action stack (top on right)
\(2\) push \(2\)
\(3\) push \(2,3\)
\(+\) pop \(3\), pop \(2\), push \(2{+}3\) \(5\)
\(4\) push \(5,4\)
\(*\) pop \(4\), pop \(5\), push \(5{\times}4\) \(20\)
  • Postfix string: 2 3 + 4 * — our calculator’s shape, with \(a=2\), \(b=3\), \(c=4\): \((a+b) \times c\).
  • Final answer: the single value left on the stack, \(20\).

Cost of the Two Applications

One pass, constant work per token. Both algorithms read every character or token exactly once, and each push/pop is \(O(1)\).

  • Balanced-parenthesis check: \(O(n)\) worst case, \(n\) = length of the expression.
  • Postfix evaluation: \(O(n)\) worst case, \(n\) = number of tokens.
  • Compare this to the naive alternative — matching brackets by scanning back and forth without a stack, which degrades toward \(O(n^2)\) on nested input.

Two structures down. Time to consolidate before Week 4 converts infix to postfix.

Three Common Mistakes

  • Forgetting the overflow/underflow check — an unchecked push past capacity or pop on top = -1 is undefined behaviour, not a graceful failure.
  • Mixing up row-major and column-major — the same \(A[i][j]\) computes to two different addresses; state which order you mean before writing the formula.
  • Treating pop as “erasing” memory — pop only moves top; the old value is logically gone but physically still sitting there until overwritten.

Week 3 Summary

  • 1D address: \(\text{addr}(A[i]) = \text{base} + i \times w\) — \(O(1)\), independent of \(n\).
  • Row-major: \(\text{base} + ((i \times c) + j) \times w\); column-major: \(\text{base} + ((j \times r) + i) \times w\).
  • Stack ADT: push/pop/peek, LIFO, top = -1 when empty — implemented here over an array.
  • Applications: balanced-parenthesis checking and postfix evaluation, both \(O(n)\) with a stack.
