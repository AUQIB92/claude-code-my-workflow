# Data Structures (PCC CS-301) — B.Tech CSE, Semester 3

Undergraduate · 3 sessions/week (lecture) + 1 lab session/week · 12 teaching weeks · Credits 4 (L-T-P: 3-0-2)

Source: institute scheme, `syllabi/Data-Structures.pdf` (pp. 40–41).

## Course description

This course builds the working vocabulary of data organization: how a program lays out data in memory, what it costs to operate on it, and how to choose the right structure for a problem. Students move from pointers and dynamic memory in C, through the linear abstract data types (stacks, queues, linked lists), into searching and sorting with formal cost analysis, and finish with the non-linear structures — trees, balanced trees, hash tables, and graphs. Students leave able to implement each structure from scratch in C, state and justify the asymptotic cost of every operation on it, and defend a structure choice against alternatives for a given workload.

## Prerequisites

Programming in C (functions, arrays, `struct`, recursion, basic file I/O). Basic discrete mathematics — sets, logarithms, summations, and proof by induction — is assumed for the complexity analysis in Week 2 onward. No prior exposure to data structures is assumed.

## Learning objectives

By the end of this course, students will be able to:
- Manage dynamic memory in C with pointers (`malloc`/`calloc`/`realloc`/`free`) and express a data structure as an abstract data type separated from its implementation (Week 1)
- Derive the space and time complexity of an algorithm, express it in the appropriate asymptotic notation, and distinguish best-, worst-, and average-case behaviour (Week 2)
- Implement stacks and queues (linear, circular, double-ended, priority) over arrays, and apply them to expression conversion, expression evaluation, and recursion problems (Weeks 3–5)
- Implement singly, doubly, and circular linked lists, and select between array and linked representations for a given access pattern (Weeks 6–7)
- Apply and analyze linear and binary search, and implement the elementary sorting algorithms with their cost analysis (Week 8)
- Implement and compare the efficient sorting algorithms (quick, merge, shell, radix, heap), and justify a choice against input characteristics (Week 9)
- Select a file organization and design a hash function with an appropriate collision-resolution scheme (Week 10)
- Implement binary trees, binary search trees, and AVL trees with their traversals and rebalancing rotations (Week 11)
- Represent graphs, traverse them with BFS and DFS, and apply Prim's, Kruskal's, and Dijkstra's algorithms to spanning-tree and shortest-path problems (Week 12)

### Rubric — Lab practicals (P1–P13)

| Criterion | Excellent | Adequate | Weak |
|-----------|-----------|----------|------|
| Correctness | Handles all cases including empty, single-element, full, and boundary inputs | Correct on typical input; boundary cases unhandled | Fails on typical input |
| Structure choice & complexity | Right structure chosen; complexity stated and justified | Right structure; complexity stated without justification | Wrong structure, or complexity absent/incorrect |
| Memory discipline | Every allocation freed; no leaks, no use-after-free, no unchecked `malloc` | Allocations freed on the main path; error paths leak | Leaks throughout, or writes past allocated bounds |
| Code quality | Clear naming, decomposed into functions, commented invariants | Readable, thin commenting | Monolithic `main`, unreadable |

### Rubric — Class Tests / End-Semester Exam (algorithm trace + analysis questions)

| Criterion | Excellent | Adequate | Weak |
|-----------|-----------|----------|------|
| Correct structure/algorithm selected | Correct choice identified and justified against alternatives | Correct choice, justification thin | Wrong or missing choice |
| Execution | Trace or derivation fully correct at every step | Minor slips in a step or an index | Major errors, method breaks down |
| Complexity analysis | Correct bound, correct case, reasoning shown | Correct bound, reasoning implicit | Bound wrong or case confused |
| Communication | Steps clearly labeled, diagrams/notation consistent | Mostly clear, some gaps | Illegible or unstructured |
