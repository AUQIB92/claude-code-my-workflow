**Important scoping note for Week 8:** this 6th edition **never uses the terms "DMA" or "IOP" (I/O Processor) as named topics** — there is no DMA or IOP subsection anywhere in the table of contents (verified by direct inspection, PDF pages 19-20/printed xv-xvi and xvi-xvii). The closest analogue is §7.3 Arbitration, which describes an I/O device acting as a bus master to transfer data directly to/from memory — functionally DMA, but the book never calls it that. **Any slide content on DMA-by-name or IOP must be phrased as general/standard treatment (citing Stallings Ch. 7, per the syllabus) rather than page-cited to this book**, per `.claude/rules/textbook-grounding.md`.

## Section-level detail (Ch. 3, Ch. 7 §7.1-7.4, for page-precise citation)

**Ch. 3:** 3.1 Accessing I/O Devices (p.96, Fig 3.1 — interconnection network) · 3.1.1 I/O Device Interface (p.97, Fig 3.2 — data/status/control registers) · 3.1.2 Program-Controlled I/O (p.97-100, Fig 3.3 — KIN/KIRQ/KIE, DOUT/DIRQ/DIE bits; the READWAIT/WRITEWAIT polling loops) · 3.1.3 An Example of a RISC-Style I/O Program (p.101-102, Fig 3.4) · 3.1.4 An Example of a CISC-Style I/O Program (p.101-103, Fig 3.5) · 3.2 Interrupts (p.103-104, Fig 3.6 — transfer of control, interrupt-service routine, interrupt latency, shadow registers) · 3.2.1 Enabling and Disabling Interrupts (p.106-107 — IE bit in PS, per-device interrupt-enable bit, 5-step interrupt-handling scenario) · 3.2.2 Handling Multiple Devices (p.107-109 — polling vs. vectored interrupts, interrupt-vector table, interrupt nesting and priority structure, simultaneous-request arbitration deferred to Ch.7) · 3.2.3 Controlling I/O Device Behavior (p.109-110 — control register interrupt-enable bit) · 3.2.4 Processor Control Registers (p.110-111, Fig 3.7 — PS, IPS, IENABLE, IPENDING; MoveControl instruction) · 3.2.5 Examples of Interrupt Programs (p.111-118, Fig 3.8-3.11 — full worked RISC/CISC programs, single-device and multi-device with IPENDING-based dispatch) · 3.2.6 Exceptions (p.116-119 — exception as generalized interrupt: error recovery, debugging trace/breakpoints, OS use) · 3.3 Concluding Remarks (p.119 — explicitly defers I/O hardware to Ch. 7, matching Week 8's own polling/interrupts-then-hardware structure).

**Ch. 7 (§7.1-7.4):** 7.1 Bus Structure (p.228, Fig 7.1-7.2 — single shared bus, address decoder in each I/O interface, memory-mapped I/O restated from Ch.3) · 7.2 Bus Operation (p.229 — bus protocol, master/slave roles) · 7.2.1 Synchronous Bus (p.230-233, Fig 7.3-7.5 — bus clock, idealized vs. detailed timing with propagation delay $t_{AM}/t_{AS}/t_{DS}/t_{DM}$, multiple-clock-cycle transfer using a Slave-ready acknowledgment for slow devices) · 7.2.2 Asynchronous Bus (p.233-236, Fig 7.6-7.7 — full-handshake protocol, Master-ready/Slave-ready fully-interlocked exchange, bus skew, trade-off vs. synchronous: simpler clock distribution but two round-trip delays per transfer) · 7.2.3 Electrical Considerations (p.236-237 — tri-state gates/bus drivers) · 7.3 Arbitration (p.237-238, Fig 7.8-7.9 — arbiter circuit, bus-request/bus-grant lines, priority-based grant scheme worked 3-master example; **this is the section that generalizes "one bus master" to "an I/O device can be a bus master to transfer data directly to/from memory" — the functional core of DMA, stated without ever using the acronym**) · 7.4 Interface Circuits (p.238-239 — six required interface functions: data/status/control registers, address decoding, timing generation, format conversion) · 7.4.1 Parallel Interface (p.239-242, Fig 7.10-7.14 — full worked keyboard-input and display-output interface circuits built on the asynchronous handshake protocol, directly extending Ch.3's KBD/DISP register model into gate-level detail).
